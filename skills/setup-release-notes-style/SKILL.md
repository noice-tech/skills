# Set Up Release Notes Style

Create or refine `.release-notes/style.md` at the repository root, using the user's preferences and the product's README, documentation, and existing public voice. Preserve useful existing guidance. Ask briefly when missing product or audience information would force invention.

Keep the guide short and concrete:

- Audience and what they care about.
- Voice: what to use and avoid.
- Product terminology.
- Public release format and bullet style.
- A few good and bad examples.

The guide serves humans and the pr, unreleased, and release-notes skills. PR summaries use its audience, voice, and terminology; final release notes also use its presentation format.

Do not duplicate or override the skills' change classifications, canonical Public summary contract, source priorities, or privacy boundaries. Do not put Git/GitHub procedures or PR templates into the style guide.

Write the guide and report its path with a brief summary. Do not invoke another skill, change PRs, or publish anything.
